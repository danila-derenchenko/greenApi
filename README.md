# GREEN-API · Telegram Messenger

Тестовое задание на React: простой интерфейс для отправки и получения текстовых сообщений Telegram через **GREEN-API**. Используется аккаунт Telegram, подключённый к инстансу GREEN-API. Telegram разрешён как альтернативный мессенджер в условиях задания.

**React 19 · TypeScript · Vite · CSS · Vitest · Playwright**

## Запуск

Нужны Node.js **22.12+** и npm. Зависимости в текущей рабочей папке уже установлены.

```bash
npm install
npm run dev
```

Откройте адрес из терминала, обычно **http://127.0.0.1:5173**.

Нажмите **«Открыть демоверсию»**, чтобы посмотреть интерфейс без регистрации и ключей. Демо явно обозначено в интерфейсе: все его сообщения и ответы локальные, запросы в Telegram не выполняются.

При повторной установке из репозитория используйте `npm ci`, чтобы установить версии из `package-lock.json`. Если локальный кэш npm недоступен из-за прав, можно задать отдельный: `npm ci --cache /tmp/green-api-npm-cache`.

## Что требуется от вас для работы с Telegram

1. Зарегистрироваться в [личном кабинете GREEN-API](https://console.green-api.com/).
2. Создать инстанс **Telegram**, выбрать доступный тариф и подключить свой Telegram-аккаунт. Для QR-авторизации: Telegram → Настройки → Устройства → Подключить устройство; отсканировать QR из GREEN-API. Дождаться состояния `authorized`.
3. В настройках инстанса:

   | Параметр | Значение | Зачем |
   | --- | --- | --- |
   | `webhookUrl` | пустая строка | Получение уведомлений через HTTP API |
   | `incomingWebhook` | `yes` | Входящие сообщения |
   | `outgoingWebhook` | `yes` | Статусы доставки и прочтения; рекомендуется |
   | `outgoingMessageWebhook` | `yes`, по желанию | Сообщения, отправленные из приложения Telegram |
   | `outgoingAPIMessageWebhook` | `yes`, по желанию | Сообщения, отправленные через API |
   | `stateWebhook` | `yes`, по желанию | Уведомления об отключении инстанса |

   Сохранить настройки и подождать около минуты. Приложение проверяет авторизацию, тип инстанса и отсутствие конфликтующего webhookUrl. Выключенный incomingWebhook не мешает входу и отправке: в чате будет небольшое предупреждение. Изменения в личном кабинете автоматически не вносятся.

4. Скопировать **`apiUrl`**, **`idInstance`**, **`apiTokenInstance`** из карточки этого инстанса и ввести в форму приложения. `apiUrl` нужен именно из карточки: сервер может отличаться от примера в поле.
5. Подготовить второго участника с Telegram и его номер телефона в международном формате. Если поиск по номеру закрыт настройками приватности, можно использовать его **`@username`**.
6. Нажать **«Новый чат»**, указать получателя, отправить сообщение и попросить его ответить из Telegram. Ответ появится в чате автоматически.

**Присылать токен, QR-код или код входа в переписку с разработчиком не требуется — введите данные локально в приложении.** BotFather, bot token, `api_id` и `api_hash` для этого решения не нужны. Регистрация и авторизация вашего Telegram — действия, которые нужно выполнить вам.

Официальная [инструкция GREEN-API для Telegram](https://green-api.com/telegram/docs/before-start/) и [настройка HTTP-получения](https://green-api.com/telegram/docs/api/receiving/technology-http-api/).

## Реализовано

| Требование | Реализация |
| --- | --- |
| React | React + TypeScript, функциональные компоненты и hooks |
| Ввод учётных данных | Форма с проверкой адреса и состояния инстанса, скрытие токена |
| Простой интерфейс мессенджера | Список чатов слева, переписка справа, входящие/исходящие сообщения, поле отправки; на телефоне отдельные экраны списка и чата |
| Создание чата по номеру | Нормализация международного номера и `checkAccount` для получения настоящего Telegram `chatId` |
| Отправка текста | `sendMessage`, Enter для отправки, Shift+Enter для переноса строки, лимит 4096 символов |
| Получение ответа | Последовательный long polling `receiveNotification` → обработка → `deleteNotification` |
| Дополнительно | Поиск по чатам, непрочитанные, статусы сообщений, черновики отдельно для каждого чата, демоверсия и встроенная помощь |

Структура экрана следует двухпанельному интерфейсу веб-мессенджера из задания. Это самостоятельное оформление, а не точная копия MAX.

## API и обработка ошибок

Все запросы идут напрямую из браузера на `apiUrl` инстанса по схеме:

```text
{apiUrl}/waInstance{idInstance}/{method}/{apiTokenInstance}
```

- `getStateInstance`, `getSettings` — проверка подключения.
- [`checkAccount`](https://green-api.com/telegram/docs/api/service/CheckAccount/) — преобразование номера или username в `chatId`. Для Telegram номер телефона и `chatId` обычно различаются.
- [`sendMessage`](https://green-api.com/telegram/docs/api/sending/SendMessage/) — POST с `{ chatId, message }`. Получение `idMessage` означает принятие сообщения в очередь. Доставка подтверждается отдельным уведомлением.
- [`receiveNotification`](https://green-api.com/telegram/docs/api/receiving/technology-http-api/ReceiveNotification/) — GET с `receiveTimeout=25`.
- [`deleteNotification`](https://green-api.com/telegram/docs/api/receiving/technology-http-api/DeleteNotification/) — DELETE по `receiptId` после обработки.

Цикл получения последовательный, без перекрывающихся запросов. После сетевых ошибок он повторяет попытки с задержкой до 30 секунд, при ошибках доступа останавливается. Выход отменяет запросы и ожидания. Web Locks защищает очередь от двух вкладок этого приложения в одном браузерном профиле; защита не распространяется на другие браузеры и интеграции. Повторные уведомления не дублируют сообщения. Статусы, пришедшие раньше ответа на отправку, сохраняются и сопоставляются с сообщением. Исходящее уведомление обновляет статус уже показанного сообщения без дублирования. Повторная отправка получает отдельный локальный идентификатор, поэтому запоздалый статус предыдущей попытки её не затрагивает.

Отправка не повторяется автоматически: это предотвращает случайные дубли при потере ответа сервера. При явном отказе можно нажать «Повторить отправку». Если результат неизвестен из-за таймаута или сетевого сбоя, интерфейс предлагает сначала проверить Telegram.

## Границы решения

- Только текст, включая текстовые сообщения с URL; без файлов, звонков и редактирования сообщений.
- Токен и переписка хранятся **только в памяти открытой страницы**, без `localStorage`, `sessionStorage`, `.env` или серверной базы. После обновления нужно подключиться заново; локальный список чатов очищается. История из Telegram не загружается.
- Очередь инстанса общая: приложение подтверждает полученные уведомления, включая неподдерживаемые типы, чтобы не блокировать следующие сообщения. Не используйте параллельно другой потребитель той же очереди.
- Это frontend-приложение: владелец вкладки видит собственные API-запросы в DevTools. Адрес назначения ограничен HTTPS-доменами `green-api.com`. Токен не выводится в сообщениях об ошибках.
- Используется системный шрифт; внешние шрифтовые сервисы не нужны.
- Для работы требуется доступ к GREEN-API и авторизованный Telegram-инстанс. Реальный обмен с аккаунтом пользователя **не проверен без его данных доступа**. Документация GREEN-API помечает Telegram API как beta.

## Проверки и сборка

```bash
npm run lint         # ESLint
npm test             # Vitest: 26 тестов
npm run test:e2e     # Playwright: 10 сценариев, desktop + mobile
npm run build        # Проверка TypeScript и production-сборка в dist/
npm run preview      # Локальный просмотр production-сборки
```

Браузерные тесты используют **Google Chrome** (`channel: 'chrome'`). Если он отсутствует, установите Chrome или замените канал в `playwright.config.ts` на установленный Chromium. Тесты автоматически запускают Vite, если он ещё не запущен.

Проверены: авторизация, неверные настройки получения, создание чата по номеру, тело `sendMessage`, входящий ответ, подтверждение очереди, повторная доставка уведомления, ручной повтор отправки, восстановление после HTTP 503, скрытый номер получателя, переключение чатов с сохранением черновиков, отображение текста без HTML-интерпретации, мобильная навигация и выход. Реальные API-запросы в этих тестах заменены контролируемыми ответами по документированному формату.

`dist/` можно разместить на статическом HTTPS-хостинге. Секреты в сборку добавлять не нужно: пользователь вводит их при подключении.

## Структура

```text
src/
  components/       # Форма подключения, чат, диалоги и помощь
  hooks/            # Жизненный цикл подключения и отправки
  lib/
    green-api.ts    # HTTP-клиент и валидация
    polling.ts      # Получение и подтверждение уведомлений
    chat-state.ts   # Состояние чатов, статусы и дедупликация
    notifications.ts # Разбор уведомлений Telegram
    message.ts      # Общая проверка текста и лимит длины
    record.ts       # Проверка объектов из внешних данных
    format.ts       # Форматирование времени
    demo.ts         # Изолированные демонстрационные данные
  types.ts
  styles.css
tests/              # Браузерные сценарии
```
